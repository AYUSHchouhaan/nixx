Overview

Two new pages were added to the web app: a task launcher at /app and a live agent chat/run view at /app/[id]. The launcher lets the signed-in developer pick a repository and branch (fetched from GitHub via Octokit using the installation token), describe a task, and start it. The run view streams the LangGraph agent's messages, tool calls, and tool results over SSE using the LangGraph SDK's useStream React hook.

/app Page

The launcher is a server component that redirects to /login when there is no session. It loads the current user's conversations and threads from Postgres and passes them to a client shell.

Repository & Branch Selection

The client shell fetches repositories from /api/github/repositories, which resolves the GitHub App installation token for the signed-in user and lists repos accessible to that installation using Octokit. When a repository is chosen, it fetches branches from /api/github/branches?owner=&repo= and pre-selects the default branch.

Starting a Task

1. User types a prompt and presses Enter.
2. POST /api/conversations  → { id }
3. POST /api/threads        → { id } (stores repoUrl, branch, title in metadata)
4. Navigate to /app/{threadId}?prompt=...&repoUrl=...&branch=...

Conversation and thread ids are both randomUUID() and are scoped to the authenticated userId, so two users never share the same thread or conversation id.

/app/[id] Page

The thread page is a server component that verifies thread ownership, fetches prior LangGraph messages via client.threads.getState, and renders the client chat UI. The chat client uses the LangGraph SDK's useStream hook with a custom FetchStreamTransport pointing at the authenticated SSE relay route.

Message Rendering

  • Human messages — right-aligned bubbles.
  • Agent messages — left-aligned bubbles.
  • Tool calls — show tool name, JSON args, result, and status.
  • Tool results — rendered as monospace code blocks.

The input stays fixed at the bottom; there is intentionally no motion animation on the composer.

SSE Streaming Flow

  1. The chat client calls stream.submit() with the user query and configurable values.
  2. FetchStreamTransport POSTs to /api/threads/[threadId]/stream.
  3. The relay verifies the session, resolves the installation token, and calls streamAgent().
  4. streamAgent() uses client.runs.stream with streamMode: ["messages-tuple", "values"].
  5. The relay forwards each LangGraph SSE chunk to the browser as event: + data: frames.
  6. useStream reassembles messages, tool calls, and tool results in React state.
// lib/agent-brain.ts
export function streamAgent(input) {
  return client.runs.stream(input.threadId, "coding", {
    input: { query: input.query, notes: input.notes ?? "" },
    config: {
      configurable: {
        thread_id: input.threadId,
        conversation_id: input.conversationId,
        sandbox_id: input.sandboxId,
        repo_url: input.repoUrl,
        branch: input.branch,
        installation_token: input.installationToken,
      },
    },
    streamMode: ["messages-tuple", "values"],
  });
}
The LangGraph thread_id equals the database thread.id, so subsequent runs resume from the latest checkpoint instead of starting fresh.

API Changes

POST /api/conversations

Now accepts an optional title. Also added a GET handler that lists the user's conversations and their threads.

// request (optional body)
{ "title": "implement rate limiting" }

// response
{ "id": "conversation-uuid" }

POST /api/threads

Now stores repoUrl, branch, and title in the thread's metadata JSONB column.

// request
{
  "conversationId": "conversation-uuid",
  "repoUrl": "https://github.com/you/repo.git",
  "branch": "main",
  "title": "implement rate limiting"
}

GET /api/threads/[threadId]

Returns the thread (with metadata) plus prior agent messages for hydration.

// response
{
  "thread": { "id": "...", "metadata": { "repoUrl": "...", "branch": "..." } },
  "messages": [ ... ]
}

POST /api/threads/[threadId]/stream

SSE endpoint. Accepts either a LangGraph-shaped payload (input.query + config.configurable) or the flat query/repoUrl/branch shape.
