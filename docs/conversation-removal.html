Why it changed

The application created one conversation for every task and immediately created one thread for it. Because LangGraph state, messages, sandbox execution, Git branches, pull requests, URLs, and authorization all used the thread ID, the conversation entity added no separate behavior. The thread is now the single durable task identity.

The new migration drops the foreign key, conversation index, threads.conversation_id, and conversations table. Existing migration history is preserved; the removal is represented by a new migration.
