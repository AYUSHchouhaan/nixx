GitHub Auth Rewrite

Implementation reference

Summary Old flow New flow Cookie contents Route behavior File-by-file changes Validation

GitHub credentials now live in cookies

I removed the GitHub App slug lookup and stopped reading the GitHub OAuth token from the database during API requests. Login resolves the authenticated user’s GitHub App installation once, then stores the OAuth access token and installation ID directly in HttpOnly cookies.

What changed from the old flow

Removed

Database token lookup

The old getAccessToken(userId) function queried the accounts table for every GitHub operation.

Removed

App slug dependency

The old error path depended on GITHUB_APP_SLUG and generated an installation URL from that slug.

Removed

App-wide installation scan

The incorrect intermediate implementation used an app token with apps.listInstallations() and matched by account login.

Changed

Per-request credential resolution

Repository, branch, run, stream, and installation-token routes now use the persisted installation cookie and mint a short-lived installation token.

New login and GitHub API flow

1
GitHub OAuth completes through Better Auth.Better Auth creates the GitHub account record and exposes the OAuth access token to the account creation hook.
2
Resolve the user’s App installation with Octokit.getInstallationId(accessToken) calls listInstallationsForAuthenticatedUser(), then finds the installation whose app_id matches GITHUB_APP_ID.
3
Store both values once in HttpOnly cookies.The OAuth token goes into GITHUB_ACCESS_TOKEN_COOKIE; the installation ID goes into GITHUB_INSTALLATION_ID_COOKIE.
4
Mint installation tokens when GitHub data is needed.API routes read the installation ID cookie and call createInstallationToken(installationId) using the GitHub App credentials.
5
Call installation-scoped GitHub endpoints.Repositories use listReposAccessibleToInstallation; branches use the repository branch endpoint through Octokit.

Cookie contents

CookieStored valuePurpose
GITHUB_ACCESS_TOKEN_COOKIEGitHub OAuth access tokenRetained as the authenticated user credential and available through getGitHubToken().
GITHUB_INSTALLATION_ID_COOKIENumeric GitHub App installation IDUsed to mint installation access tokens without another DB lookup or installation discovery request.

Cookie values are stored directly. Cookies are HttpOnly, use SameSite=Lax, have a root path, and become Secure in production.

Route behavior

RouteBehavior after the rewrite
GET /api/github/repositoriesChecks the Better Auth session, reads the installation ID cookie, mints an installation token, then calls fetchRepositories().
GET /api/github/branches?owner=&repo=Checks the session and query parameters, mints an installation token from the cookie ID, then calls fetchBranches().
GET /api/github/installation-tokenReturns a short-lived installation token based on the persisted installation ID. It does not discover the installation or query the accounts table.
POST /api/threads/[threadId]/runUses the cookie-backed installation ID when passing GitHub access to the agent run.
GET /api/threads/[threadId]/streamUses the same cookie-backed installation token flow for streamed agent execution.

Validation

Type checking: Passed with bun run check-types.

Lint: Passed with bun run lint.

Reference scan: No remaining web references to getAccessToken, getInstallationToken, GITHUB_APP_SLUG, getAppSlug, or apps.listInstallations().

Runtime requirements

The login hook requires BETTER_AUTH_SECRET. GitHub App token creation still requires GITHUB_APP_ID and GITHUB_PRIVATE_KEY. The OAuth provider continues to require GITHUB_CLIENT_ID and GITHUB_CLIENT_SECRET.
