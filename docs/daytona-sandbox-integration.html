Overview

The sandbox worker no longer executes on the local filesystem. It now provisions and drives real Daytona sandboxes through the @daytonaio/sdk package. Every agent run gets an isolated remote sandbox, the repository is cloned inside it, and all read / search / shell / file-mutation commands run against that sandbox.

┌─────────────────────┐ Queue A (BullMQ/Redis) ┌──────────────────────┐ │ agent-brain │ agent-to-sandbox │ sandbox-worker │ │ (LangGraph + HTTP) │ ───────────────────────────▶│ (Daytona SDK client) │ │ │ │ │ │ SandboxClient │ ◀───────────────────────────│ Daytona API │ │ (await result) │ sandbox-to-agent │ │ │ └─────────────────────┘ Queue B └────────┼──────────────┘ ▲ ▼ │ HTTP POST /run ┌─────────────────────┐ ┌─────────────────────┐ │ Daytona sandbox │ │ web │ │ /home/daytona/ │ │ (Next.js backend) │ │ git clone + exec │ └─────────────────────┘ └─────────────────────┘

Only apps/sandbox-worker changed. The agent graph, agent-brain, web, and the @repo/contracts message contract are untouched.

daytona.ts

The singleton client and shared constants live here.

import { Daytona } from "@daytonaio/sdk";
import type { CreateSandboxFromSnapshotParams } from "@daytonaio/sdk";

export const DAYTONA_IMAGE_NAME = "daytonaio/langchain-open-swe:0.1.0";
export const DAYTONA_SNAPSHOT_NAME = "open-swe-vcpu2-mem4-disk5";
export const SANDBOX_ROOT_DIR = "/home/daytona";

export const DEFAULT_SANDBOX_CREATE_PARAMS: CreateSandboxFromSnapshotParams = {
  user: "daytona",
  snapshot: DAYTONA_SNAPSHOT_NAME,
  autoStopInterval: 15,
  autoDeleteInterval: 0,
};

let daytonaInstance: Daytona | null = null;

export function daytonaClient(): Daytona {
  if (!daytonaInstance) {
    daytonaInstance = new Daytona();
  }
  return daytonaInstance;
}

new Daytona() reads DAYTONA_API_KEY (and optional DAYTONA_API_URL / DAYTONA_TARGET) from the environment.

provision.ts

Keeps the same SandboxProvisionResult contract and the https://github.com URL guard, but provisions through Daytona. 

const sandboxRegistry = new Map<string, Sandbox>();

function sandboxName(sandboxId: string): string {
  return `nixx-${sandboxId}`;
}

export function repoPath(sandboxId: string): string {
  return path.posix.join(SANDBOX_ROOT_DIR, sandboxId);
}

export async function getSandbox(sandboxId: string): Promise<Sandbox> {
  const cached = sandboxRegistry.get(sandboxId);
  if (cached) return cached;

  const sandbox = await daytonaClient().get(sandboxName(sandboxId));
  sandboxRegistry.set(sandboxId, sandbox);
  return sandbox;
}

Provisioning flow:

  1. Reject non-GitHub HTTPS URLs.
  2. daytona.get(name); on not-found, daytona.create({ ...params, name }).
  3. Check whether the repo is already present via sandbox.fs.listFiles.
  4. If absent, shallow-clone with the installation token.
  5. Persist git auth + author identity so the later PR push works.
await sandbox.git.clone(
  input.repoUrl,
  sandboxDir,
  input.branch,
  undefined,
  "x-access-token",
  input.installationToken,
  false,
  1,
);

await sandbox.git.setConfig(
  "http.extraheader",
  `AUTHORIZATION: basic ${auth}`,
  "local",
  sandboxDir,
);
await sandbox.git.configureUser("Nixx", "noreply@nixx.dev", "local", sandboxDir);
await sandbox.git.setConfig("commit.gpgsign", "false", "local", sandboxDir);

executor.ts

The signature changed from executeSandboxCommand(root, ...) to executeSandboxCommand(sandbox, repoDir, ...). Output strings and error formats are preserved so the agent sees the same results.

CommandNew implementation
read_filesandbox.fs.downloadFile → toString("utf-8")
globsandbox.fs.searchFiles, union results, strip repoDir/ prefix
grepsandbox.fs.findFiles, unique file paths, slice to 5
run_commandsandbox.process.executeCommand(command, repoDir)
create_filemkdir -p parent, then sandbox.fs.uploadFile
edit_filedownloadFile → apply ordered replacements → uploadFile
gitsandbox.process.executeCommand("git ...", repoDir) passthrough
git stays a shell passthrough. Daytona's Git API has no fetch, and the agent sends free-form args (fetch origin <branch>, add -A -- :!node_modules ..., commit --allow-empty, etc.) that must be forwarded verbatim.

main.ts

import "dotenv/config";

if (!process.env.DAYTONA_API_KEY) {
  console.error("DAYTONA_API_KEY is required");
  process.exit(1);
}

// provision job
const result = await provisionSandbox({
  sandboxId: data.sandboxId,
  repoUrl: data.repoUrl,
  branch: data.branch,
  installationToken: data.installationToken,
});

// command job
const sandbox = await getSandbox(data.sandboxId);
const result = await executeSandboxCommand(
  sandbox,
  repoPath(data.sandboxId),
  data.command,
  data.args,
);

Contract Impact

None. SandboxProvisionResult.sandboxPath now carries a remote path such as /home/daytona/<sandboxId> instead of a local one. It is informational only — the agent checks result.error, not the path.

SandboxClient, BullMqSandboxClient, queue messages, graph nodes, and agent tools all remain unchanged.

Running the System

# install
bun install

# set the Daytona key in apps/sandbox-worker/.env
# DAYTONA_API_KEY=...

# start Redis, then run these in separate terminals:

# 1. sandbox worker
bun run dev --filter=sandbox-worker

# 2. agent brain
bun run dev --filter=agent-brain

# 3. web (primary backend)
bun run dev --filter=web

Verification

  • All packages typecheck with bun run check-types.
  • Trigger POST /api/threads/:threadId/run with a real repo URL.
  • Confirm the repo is cloned into a fresh Daytona sandbox.
  • Confirm read / glob / grep / run / create_file / edit_file return correct results.
  • Confirm the PR flow succeeds — proof that clone-time git auth persisted into the sandbox.
  • Confirm a second run against the same sandboxId reuses the sandbox without re-cloning.
